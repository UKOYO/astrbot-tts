# TTS 语种自由

从陪伴插件里独立出来的一段：**正文 → 朗读稿 → 语音**。

陪伴插件保持不动，这个插件只管语音这一环，方便单独调语种、口白风格、供应商和触发策略。

> 插件显示名是「TTS 语种自由」，内部标识仍是 `astrbot_plugin_tts_studio`（目录名别改）。

> 这一版的核心取向：**文字只出中文，语音只出目标语种**，两边互不干扰，谁都不等谁。

---

## 一、它现在怎么跑

```
用户消息
   ↓
人格正常生成中文正文
   ↓
[本插件] on_decorating_result 拿到本轮正文
   ↓
sanitizer 剥掉 { } 画面描写、括号舞台指示、Markdown、颜文字
   ↓
后台任务：中文正文 →（对话模型）→ 目标语种朗读稿
   ↓
后台任务：朗读稿 →（TTS 供应商）→ 音频文件
   ↓
context.send_message 单独补发一条语音
   ↓
文字早就发出去了，语音晚两三秒跟上来
```

- **文字永远是中文正文**，原样发送，一个字都不改。
- **语音永远是目标语种朗读稿**，正文和朗读稿是两条独立的线。
- 任何一步失败都只留日志，不会影响文字消息。

### 语音投递回执（`voice_log_notice`）

followup 模式下语音是插件后台补发的，模型侧只有那串中文，
所以它本来「不知道自己出过声」，下一条消息里被问「你刚才念的那句」就会答不上来。

补法很轻：

```
语音补发成功
   ↓
本会话留一条短记录（时间 / 语种 / 朗读稿开头 120 字，最多 3 条）
   ↓
下一轮 on_llm_request 时拼进 system_prompt 末尾
   ↓
注入一次即刻清空；超过 15 分钟（VOICE_NOTE_TTL）自动丢弃
```

- 只写 `system_prompt`，**不动对话历史**，也不刷新人格上下文。
- 只对「刚发过语音的那个会话」生效，其它会话完全无感。
- 关掉 `voice_log_notice` 就退回原来的纯单向行为。

### 头像线索（`avatar_clue`）

事件里没有头像字段，模型本来「看不见对方长什么样」，
所以被问「我这头像怎么样」只能硬编。

补法是拼一条 QQ 头像的公开直链，拉回来存一份，再算一个 dHash 指纹：

```
本轮开口前
   ↓
直链拉图（q1.qlogo.cn，不通就退 q.qlogo.cn）
   ↓
和上次的指纹比：差 ≤ 6 bit 就当同一张
   ↓
第一次见 / 换脸了 → 走一次视觉转述，压成一句话存下来
   ↓
拼一行塞进 system_prompt
```

几个刻意的取舍：

- **指纹没变就闭嘴**。同一张脸的描述只说一次，之后每轮不再重复注入，
  省 token，也免得模型天天念叨「你这头像真好看」。
- **15 分钟窗口**（`REFRESH_SECONDS`）内不重复拉图，不会每句话都去打人家 CDN，
  也不至于换个头像过一天才发现。
- **不做身份判断**。转述提示词里明确要求不推测性别、年龄、职业，只说画面本身。
- **拉不到就算**。整条线包在 try 里，网络不好时静默跳过，绝不拖累正常对话。
- 默认**只在私聊开**。群里人多，一个个拉头像又慢又吵，要开就显式改 `avatar_scope`。

和语音回执一样，这条线索只写 `system_prompt`，不动对话历史；
想要完全安静就把 `avatar_clue` 关掉。

### 两种发送方式（`send_mode`）

| 模式 | 行为 | 适合 |
| --- | --- | --- |
| `followup`（默认） | 文字立刻发出，转写与合成全在后台，完成后单独补一条语音 | 追求响应速度，文字不卡 |
| `attach` | 先转写合成，再和文字一起发出 | 想文字和语音严格成对、一起到达 |

`followup` 下同一会话是串行的，保证语音到达顺序和聊天顺序一致；插件卸载时会自动取消未完成的后台任务。

## 二、安装与 AstrBot 设置

### 1. 放插件

1. 把 `astrbot_plugin_tts_studio` 整个目录放进 `data/plugins/`
2. WebUI → 插件页 → **重载插件**
3. 确认插件列表里出现「TTS 语种自由」

> 显示名是「TTS 语种自由」，内部标识和目录名仍是 `astrbot_plugin_tts_studio`，目录名别改，改了加载不到。

### 2. 先准备两个服务提供商

WebUI →「服务提供商」，需要两样东西：

| 用途 | 类型 | 建议 |
| --- | --- | --- |
| 转写朗读稿 | 对话模型 | 挑一个快的小模型（如 `deepseek-flash`）。这一步只做「中文 → 目标语种口语」，不需要聪明，只需要快 |
| 合成语音 | TTS | Fish Audio（`fishaudio_tts_api`）：填 `api_key`、`model`（如 `s2.1-pro-free`）、参考音色 `fishaudio-tts-reference-id`，保存后记下它的 **provider ID** |

音色就是参考音频。想换腔调、换人设，本质上就是换这个 `reference_id`。

### 3. 插件配置

打开插件配置，至少填这几项：

- **主用户 ID**：你的 QQ 号（必填，留空会对所有私聊生效）
- **文本转换模型**：填上面那个快模型，不要留空跟随会话
- **TTS 供应商**：填 Fish Audio 的 provider ID
- **语音语种**：默认 `ja`
- **发送方式**：先留 `followup`（文字不卡）

### 4. 唤醒前缀（指令怎么发）

AstrBot 的指令受唤醒前缀约束，本机当前前缀是 `大魔王` / `唯笑`：

- **私聊**：不需要前缀，直接发 `tts 状态`
- **群聊**：需要前缀，发 `大魔王 tts 状态`
- 前缀在 WebUI → 配置 → `wake_prefix` 里改

### 5. 关掉会打架的三处

| 位置 | 设置 | 为什么要关 |
| --- | --- | --- |
| 陪伴插件 | `enable_tts_enhancement` = false（顶层与 `voice_action_config` 各一处） | 它也会挂语音、也会往提示词里注入双语要求 |
| AstrBot 内置 TTS | `provider_tts_settings.trigger_probability` 保持 0 | 不为 0 时它会自己把回复转成语音 |
| 其它语音类插件 | 同上 | 一次回复只留一个语音出口 |

### 6. 第一次验证

1. `tts 状态` —— 看面板里的语种、模型、供应商对不对
2. `tts 试读 今天天气不错` —— 完整走一遍转写 + 合成
3. 正常聊一句 —— 文字先到，语音晚两三秒跟上

依赖：AstrBot `>= 4.22.0`，用到 `on_decorating_result`、`context.send_message`、provider 的 `text_chat` 与 `get_audio`。

## 三、指令

```
tts                查看状态面板
tts 状态           同上
tts 开启           打开总开关
tts 关闭           关闭总开关（文字照常，不再合成）
tts 语种日语       本会话切到标准日语（东京腔）
tts 语种关西腔     本会话切到关西腔日语
tts 法语           可以不带「语种」两个字
tts 语种默认       本会话取消覆盖，回到面板的全局语种
tts 试读 今天天气不错    立刻走一遍转写 + 合成，用来验证链路
```

**语种是按会话记的。** 每个私聊、每个群各存一份，改一个不影响别人：
在 A 私聊里发 `tts 语种日语`，B 群那边还是面板里的默认值。
指令改的是「当前会话」，不是面板；没单独设过的会话永远跟着面板的全局语种走。
这份记录写在 `plugin_data/astrbot_plugin_tts_studio/session_languages.json`，
插件重载、重启 AstrBot 都还在，想全部清掉删这个文件就行。

状态面板会显示：开关、本会话语种（是否单独设过）、全局面板语种、已单独设过的会话数、
自定义通道、触发范围、主用户、转换模型、TTS 供应商、发送方式。

### 加一个语种／腔调：改配置，不用改代码

上表这些内置语种是代码里的默认值；**想改某个语种的写法与声学取向、或者自己加一条通道，
在配置面板的 `language_profiles` 里写一段 JSON 就行**，不用碰 `main.py`：

```json
{
  "aave_wc": {
    "label": "美国俚语黑人西海岸口音",
    "aliases": ["西海岸", "黑帮", "帮派腔"],
    "guard": "latin",
    "pitch": 0.94,
    "tempo": 0.96,
    "eq": "equalizer=f=180:t=h:width_type=o:width=1.2:g=4.5",
    "prompt": "这一路只做一件事：把{char}的话改写成美国西海岸街头帮派腔的英文朗读稿。……"
  }
}
```

- `label` 显示名，`aliases` 是「tts 语种XXX」能认的简称，两者都会自动并进内置表；
- `guard` 语种护栏，可选 `kana`（假名）／`cjk`（汉字）／`hangul`／`latin`／`cyrillic`／`arabic`／`none`；
  内置语种不写就沿用原来的护栏，自定义语种不写则不拦；
- `pitch` / `tempo` / `eq` 只在这个语种生效的声学后处理：音高倍率、语速倍率、ffmpeg 滤镜链；
- `prompt` 只在这个语种生效的转写规则，会拼在通用规则后面。

**只写想覆盖的字段**，没写的沿用内置默认值；`language_profiles` 留空就是纯内置行为。

懒得从零写？插件目录里的 **`language_profiles.example.json`** 就是内置通道的原样导出，
复制整段进面板就能直接改。里面 `prompt` 是一行长字符串，**换行写成 `\n`**、
引号记得转义，改完存盘再发一条消息试听就行。

### 规则里别写死人格名字

写进 `extra_conversion_prompt` 或 `prompt` 的文本可以用占位符，运行时从配置填：

| 占位符 | 替换成 |
| --- | --- |
| `{char}` | `persona_bot_name`（留空显示「角色」） |
| `{user}` | `persona_user_name`（留空显示「对方」） |
| `{user_ids}` | `primary_user_ids` 里列的用户 ID |

同一份 `prompt` 因此可以直接分享给别人，对方只填自己的名字就能用。

## 五、配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `enable` | 开 | 总开关，关掉后完全不介入发送 |
| `trigger_scope` | `primary_private` | 触发范围：仅主用户私聊／所有私聊／所有会话 |
| `primary_user_ids` | 空 | **建议必填**，一行一个或逗号分隔，OneBot 填 QQ 号 |
| `voice_language` | `ja` | 全局默认朗读稿语种。`ja` = 标准日语（东京腔），关西腔是 `ja_kansai`，西海岸是 `aave_wc`；单个会话可以用指令单独覆盖 |
| `conversion_provider_id` | 空 | 转写用的对话模型，建议指定一个快模型，别跟随会话 |
| `tts_provider_id` | 空 | TTS 供应商，建议指定，别跟随会话 |
| `send_mode` | `followup` | 见上文两种发送方式 |
| `kana_guard` | 开 | 语种护栏，转写没变成目标语种就跳过语音 |
| `extra_conversion_prompt` | 空 | 追加在转写提示词后面的规则，写口癖、语气、称呼约定，可用 `{char}`／`{user}` 占位 |
| `language_profiles` | 空 | 语种专属通道，JSON；提示词、护栏、音高／语速／EQ 都写这里，见上文「加一个语种」 |
| `persona_bot_name` | 空 | 规则里 `{char}` 的替换值 |
| `persona_user_name` | 空 | 规则里 `{user}` 的替换值 |
| `intensity_pitch` | 开 | 按拟声词密度自动抬音高（日常不动／私密 ×1.08／高峰 ×1.12），不需要就关 |
| `pitch_private` | 1.08 | 私密段音高倍率 |
| `pitch_peak` | 1.12 | 逼近高潮音高倍率 |
| `intensity_markers` | 空 | 空格／逗号分隔的激烈度关键词，留空用内置中文拟声表 |
| `min_chars` | 1 | 短于这个字数不合成 |
| `max_chars` | 400 | 朗读稿超过就截断，**越长合成越慢**，建议 300~400 |
| `hard_max_chars` | 800 | 正文长过这个数就整条不出语音 |
| `min_interval_seconds` | 2.0 | 同一会话的最小间隔，防抖 |
| `strip_parenthetical` | 开 | 剔除括号里的舞台指示 |
| `strip_emoji` | 开 | 剔除颜文字与 emoji，最容易让声码器破音 |
| `keep_visible_text` | 开 | 仅 `attach` 模式下生效；`followup` 下文字总是先发 |
| `skip_when_contains_media` | 开 | 本轮已经带图／语音时不重复合成 |
| `voice_log_notice` | 开 | 语音补发后留短回执，下一轮注入 system_prompt，让模型知道「自己确实出过声」 |
| `avatar_clue` | 开 | 头像线索总开关，把当前头像压成一句话注入 system_prompt |
| `avatar_scope` | `private` | 头像线索范围：`private` 仅私聊／`primary` 仅主用户／`all` 所有会话／`off` 关闭 |

## 六、注意事项

1. **和陪伴插件的「TTS 强化」不能同时开**
   两套都会往消息里挂语音、都会往提示词里注入双语要求，同时启动会打架。
   切到本插件前，把陪伴插件的 `enable_tts_enhancement` 关掉（顶层和 `voice_action_config` 里各有一处）。

2. **改完必须重载**
   配置和代码都是启动时读进来的。改配置不重载＝没改。

3. **主用户 ID 一定要填**
   留空时 `primary_private` 不会过滤发送者，等于对所有私聊生效。

4. **`max_chars` 和 `hard_max_chars` 是两件事**
   前者是朗读稿截断长度，后者是「干脆不合成」的门限。想让长回复也有语音，就别把 `hard_max_chars` 压太低。

5. **转写走独立会话**
   转写用 `umo::tts` 这个独立 session，不会把朗读稿请求塞进人格对话历史，避免污染上下文、也避免历史越滚越慢。改这块时别图省事退回原 session。

6. **腔调跟的是音色，不是文本**
   Fish Audio 这类克隆模型只认 `reference_id`，韵律全跟参考音频走。
   所以关西腔、粤语这些「腔调」只有文本层面到位，真人腔调得换一个对应的参考音色才可能出来。
   多语种同理：同一个音色泛化到十几门语言，能读，但会带口音。

7. **护栏会静默跳过**
   `kana_guard` 判定「转写结果不像目标语种」时，这条就**不出语音**，只在日志里留一行。
   这是故意的：宁可这条没声音，也不要让声码器念着中文原文出怪音。

8. **日志关键字 `[TTSStudio]`**
   一次正常链路会有 `已追发语音: N 字 → 路径`。看到「跳过合成: xxx」就知道卡在哪一步了。

9. **含图回复不合成**（默认）
   图片、语音、视频、文件都会让本轮跳过，避免消息里挂两条媒体。

10. **冷却**：`min_interval_seconds` 默认 2 秒，连发消息时中间几条可能没有语音，这是防堆叠，不是坏了。

11. **回执不等于历史**
    投递记录只拼在 system_prompt 上，注入完就清，所以它不会进对话历史、不会被反复回放，
    也不会让上下文变长。想让它彻底闭嘴，把 `voice_log_notice` 关掉即可。
    另外 `context.send_message` 只回 `bool`，拿不到 message_id，
    所以「用户直接引用语音消息」这条路暂时没法回填原文，只能靠回执兜。

## 七、排错速查

| 现象 | 先看这里 |
| --- | --- |
| 完全没语音 | `enable` 是否开、是不是主用户私聊、正文是否超过 `hard_max_chars`、本轮是否带图 |
| 语音念的是中文 | `kana_guard` 是否被关掉、转写模型是否指错、转写是否超时退回原文 |
| 语音来得很慢 | 转写模型是否用了大模型（换 flash 级别）、`max_chars` 是否过长、TTS 供应商网络 |
| 文字也没了 | 只在 `attach` 模式下会发生，检查 `keep_visible_text` |
| 一次出两条语音 | 陪伴插件的 TTS 强化没关干净 |
| 语音顺序乱 | 正常情况有会话锁串行；检查是不是被人为改掉了 `_locks` |
| 模型不承认自己发过语音 | `voice_log_notice` 是否被关掉、记录是否已过 15 分钟 TTL |
